Three directions for the InsureShield header

Each option keeps every link the site has today. They differ in how much the header moves, and in how strongly it carries the illustration style already on the new Shipping Insurance page. All three can be tried below on desktop and mobile.

At a glance

One menu, three levels of motion

ARecommended

Morph

A single floating panel that reshapes and slides as you move between menu items, like the reference sites. The motion shows that every menu belongs to one system, so moving from Shipping Insurance to Resources feels like one continuous move instead of two separate pop-ups.

BMinimal

Quiet

A full-width panel that docks under the header, with a thin teal underline that slides to the open item. Calm, highly scannable, and the cheapest to build and maintain. It is closest to today's layout, so returning visitors relearn nothing.

CExpressive · three.js

Illustrated

A full-width panel with a live 3D scene drawn in the site's isometric line style. Each section builds its own object (parcel and shield, stacked layers, a globe), and the object reacts as you point at links. It carries the most brand presence and has the highest build and performance cost.

Principles

What the header has to do

The header is the only part of the site that is on every page, so its first job is to help people find their way. Motion is used only where it explains what just happened.

Orient first

A visitor should know where they are and where each menu leads before any animation plays. Labels and one-line descriptions do that work; motion supports them.

Motion explains

Every movement answers a question: where did this panel come from, which item opened it, and how does it relate to the last one? Nothing in the menu loops or moves just for decoration.

Name by task

Groups use the visitor's words ("Coverage by shipment", "Get started"), not our org chart. That helps first-time shippers pick a path without knowing product names.

Two doors always open

Getting a quote and filing a claim are the two most time-sensitive jobs. Both are one step away on every page, on desktop and mobile.

Calm and inclusive

Works with keyboard, screen reader, touch and reduced motion. Targets are at least 44px (Momentum control size), and timing comes from Momentum motion tokens.

Interaction & accessibility

Behavior shared by all options

SituationBehavior
Pointer enters a menu itemOpens after an 80ms intent delay, so sweeping across the header doesn't flash panels. When a panel is already open, moving to another item switches immediately.
Pointer leaves the header or panelCloses after a 240ms grace period, so a diagonal path from the item to the panel doesn't close it.
Click or tap a menu itemToggles the panel. On touch devices hover is ignored and only taps count.
KeyboardTab moves between items. Enter or Space opens. ↓ opens and moves focus to the first link. Esc closes and returns focus to the item. Tabbing out of the header closes it.
ScrollingKeeps the current hide-on-scroll behavior: the header hides when scrolling down and returns when scrolling up. Any open panel closes on scroll.
Mobile drawerThe menu button shows its state ("Menu"/"Close"). Focus stays inside the drawer while open, Esc closes it, the page behind doesn't scroll, and focus returns to the menu button on close. "Get a quote" and "Claims" stay pinned at the bottom.

Accessibility

  • Uses the disclosure pattern: <nav aria-label="Main"> with buttons that have aria-expanded and aria-controls. It does not use role="menu", which is meant for app menus, not site links.
  • Hidden panel content is inert, so keyboard focus never lands on links you can't see.
  • The current section is marked visually and with aria-current="page" on the matching link.
  • Teal (#0A8080) on white is about 4.8:1, which passes WCAG AA for text. Focus uses the Momentum focus ring (2px, 4px offset).
  • With reduced motion on, morphs and slides become instant swaps and the 3D scene shows a single still frame.
  • In Option C the canvas is decorative (aria-hidden), and every piece of meaning is also in text.

Motion tokens

  • Hover color, chevron, link arrow--m-duration-fast · 100ms
  • Panel open and close fade, content crossfade, B underline--m-duration-base · 200ms
  • A morph (size and position), C panel height, mobile drill-down--m-duration-slow · 320ms
  • Moving between states--m-easing-standard
  • Panel appearing--m-easing-enter
  • Panel leaving--m-easing-exit

In production, Option A's resize should use transforms (FLIP) rather than animating width and height, to hold 60fps on low-end laptops.

Recommendation

Ship Option A, and keep the illustrations for one place where they earn it

Morph gives stakeholders the motion they saw on the reference sites, and every movement has a purpose: it shows which item opened the panel and how the menus relate. It keeps descriptions and icons for first-time shippers, costs little in page weight, and can be built from Momentum's existing popover, link and button parts.

  1. Phase 1: Build Option A with the content changes once they're approved. Test with 5–6 shippers, including one claimant scenario ("you need to file a claim today").
  2. Phase 2: Try one of Option C's 3D objects inside Option A's Shipping Insurance panel as its featured item. Keep it only if it holds 60fps and doesn't slow task completion.
  3. Fallback: If the header must ship on AEM pages before the React rebuild finishes, start with Option B. It uses the same content and the same shared behavior.
